04

三条命令,建起一套高可用块存储。

从裸盘到跨机架三副本 + NFS 高可用导出。

root@node-1 — haify
# 1 · 用裸盘建存储池
haify pool create --name vg0 --node node1 --disks /dev/vdb

# 2 · 建 DRBD 资源:自动放置,三副本强制跨机架
haify resource create --name data --size 100G \
  --replicas 3 --replicas-on-different rack

# 3 · 导出为高可用 NFS(浮动 VIP 自动跟随主节点)
haify gateway nfs create --resource data \
  --service-ip 192.168.1.200/24 --export-path /data

# 就绪 —— 客户端始终访问 VIP,故障时约 70s 自动接管
mount -t nfs 192.168.1.200:/data /mnt

05

常见问题

关于 Haify 的定义、平台、高可用与 Kubernetes 的直接回答。

Haify 是什么?

Haify 是一套基于 DRBD 的软件定义存储控制面,提供强一致同步复制、智能副本放置、自动故障切换、NFS/iSCSI/NVMe-oF 网关与 Kubernetes CSI。

Haify 能跑在哪些平台上?

CPU 支持 x86_64、aarch64(含鲲鹏、飞腾)与 loongarch64(龙芯);操作系统支持 Debian、Ubuntu、RHEL 系以及麒麟、统信 UOS。可在完全离线的环境中部署。

Haify 和 Ceph、LINSTOR 有什么区别?

与 Ceph 相比,Haify 运维更轻——单一控制面经 SSH 编排,无需 MON/OSD/MGR 组件。与 LINSTOR 相比,Haify 不需要在每个存储节点上常驻代理进程,控制面通过 SSH 直接管理节点。

Haify 的高可用如何工作?故障切换多快?

Haify 用 drbd-reactor promoter 编排有序启动栈,浮动 VIP 跟随主节点漂移。节点硬故障后约 70 秒自动接管;quorum 仲裁防止脑裂,DRBD 同步复制保证单节点故障零数据丢失,客户端始终访问同一个 VIP。

Haify 支持 Kubernetes 吗?

支持。Haify 提供 Kubernetes CSI 驱动,可动态供给持久卷并做拓扑感知调度。节点硬故障后由 node 插件安全提升本地副本接管,数据完好。已在 x86_64 与 aarch64 的 k3s 集群上端到端验证。

Haify 的数据是怎么复制的?会丢数据吗?

Haify 基于 DRBD 做同步多副本复制,写入返回时数据已落盘多个节点。可按容量自动放置,或强制副本跨机架分布。配合 quorum 仲裁,单节点故障不丢数据;还可选 WAN 异步复制做跨数据中心容灾。
