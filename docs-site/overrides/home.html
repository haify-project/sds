Replicated block storage for your own Linux servers.

SDS runs DRBD 9 across your nodes from one controller: storage pools, synchronously replicated volumes, automatic failover, NFS, iSCSI and NVMe-oF exports, off-site backups and Kubernetes volumes. Nothing extra runs on the storage nodes; the controller reaches them over SSH.

What it manages

One CLI, a web UI and an API cover the life of the storage, from raw disks to the volume a workload mounts.

Storage
Pools on LVM, LVM-thin or ZFS, with an optional SSD cache. Resources placed automatically by free space and failure domain, resized online, encrypted at rest with LUKS2.
Availability
Synchronous replication with quorum and tiebreakers. drbd-reactor moves services and a floating IP to a healthy replica. The controller itself can fail over the same way.
Access
NFS, iSCSI and NVMe-oF gateways that follow their volume across failovers. Diskless clients read and write over the network. A CSI driver for Kubernetes and a storage plugin for Proxmox VE.
Protection
Scheduled snapshots, and scheduled incremental backups to S3, SMB or WebDAV that restore onto a rebuilt or a different cluster. Asynchronous disaster-recovery replicas over a TCP tunnel that works through NAT.
Operations
Alerts on degraded replicas, lost Primaries and full pools, delivered to webhooks and chat. A daily inspection that reports problems with the command that fixes them. Prometheus metrics, RBAC, audit log, TLS, and an MCP server for AI assistants.

From disks to an NFS share

With the controller installed and SSH access to each node, a replicated, failover-ready export takes four commands.

  1. Register the storage nodes.

    sds node register --name node1 --address 192.0.2.11 sds node register --name node2 --address 192.0.2.12

  2. Turn a disk on each node into a thin pool.

    sds pool create --name pool0 --type lvm-thin --nodes node1,node2 --devices /dev/sdb

  3. Create a 10 GiB volume replicated to both nodes.

    sds resource create --name data --port 7001 --size 10G --nodes node1,node2 --pool pool0

  4. Export it over NFS on an address that moves with the Primary.

    sds gateway nfs create --resource data --service-ip 192.0.2.200/24 --export-path /data

How it is built

One controller, no node agent. sds-controller keeps its state in an embedded database and runs every change on the nodes over SSH.

DRBD does the replication. Writes are acknowledged once every connected replica has them; drbd-reactor decides where each service runs.

Everything goes through one API. The CLI, the web UI, the CSI driver, the Proxmox plugin and the MCP server all call the same gRPC and REST endpoints.
